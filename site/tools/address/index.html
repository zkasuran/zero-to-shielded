What each kind means

Look at how it starts

The first letters tell you most of the story. The checksum tells you nobody changed a character.

  • u1Shielded

    Unified address

    A u1 address is a unified address. It bundles one or more receivers. A receiver is one way to get paid. The address Zodl shows as Zcash Shielded Address starts with u1 and holds only shielded receivers. An address made by another wallet may also hold a transparent receiver.

    This checker checks the prefix and the checksum. It does not open the address to list the receivers inside.

    Checksum: Bech32m

  • zs1Shielded

    Sapling address

    Older Sapling addresses start with zs1. Sapling is a shielded pool, so payments to this address are shielded. Your Zodl shielded address starts with u1 instead.

    Checksum: Bech32

  • t1Transparent

    Transparent address

    It starts with t1 and works like a Bitcoin address. Anyone can see what is sent to it. Paying it from your shielded balance is unshielding: the amount and this address are public and you cannot add a note.

    Checksum: Base58Check

  • t3Transparent

    Transparent address (P2SH)

    Transparent addresses start with t1 or t3. This one starts with t3. Anyone can see what is sent to it, like Bitcoin.

    Checksum: Base58Check

  • tex1Transparent

    TEX address

    A TEX address starts with tex1. It is a form of a t1 address that can only be paid from transparent funds. Some exchanges use tex1 addresses for deposits. When you pay one from Zodl, Zodl does the two steps for you. The amount and the address are public.

    Checksum: Bech32m

How the checker works

It runs on your device and never sends what you paste anywhere. It follows ZIP 316 (unified addresses), ZIP 320 (TEX addresses) and section 5.6 of the Zcash protocol spec.

  • t1 and t3 use Base58Check. The checker runs SHA-256 twice and compares the last 4 bytes.
  • zs1 uses Bech32. u1 and tex1 use Bech32m. The checker tests the checksum, the prefix and the length.
  • u1 limit: a unified address is scrambled on purpose (a step called F4Jumble). This checker does not unscramble it, so it does not list the receivers inside. It checks the checksum and the prefix only.

Its tests use official public test vectors from the zcash-test-vectors, zcash and librustzcash projects, plus changed copies that must fail.
